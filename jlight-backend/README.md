# JLIGHT v4 — Python Backend

Health Intelligence System · Team Fiada Mothapo · Hackathon 2026

## What This Is

A production Python backend for JLIGHT — replacing the browser-based JavaScript
implementation with a proper server-side stack:

- **Flask** REST API (all endpoints)
- **scikit-learn + SciPy** ML engine (regression, Z-score, Westgard, risk stratification)
- **Bioinformatics review** of authorised, externally generated outputs with source provenance and QC context
- **pandas + NumPy** data ingestion and CSV analysis
- **PostgreSQL** persistent storage (audit trail, cards, uploads)
- **Docker** containerised deployment

## Quick Start (Local)

```bash
# 1. Clone and enter directory
cd jlight-backend

# 2. Install dependencies
pip install -r requirements.txt

# 3. Copy and configure environment
cp .env.example .env
# Edit .env with DATABASE_URL (optional) and SUPABASE_URL (required for protected routes)

# 4. Run tests
python3 tests/test_all.py

# 5. Start server
python3 api/app.py

# Server runs at http://localhost:5000
```

## Authentication

The API uses the shared verifier in `api/security.py`. Set `SUPABASE_URL` to the project URL; the issuer defaults to `${SUPABASE_URL}/auth/v1` and the JWKS endpoint defaults to `${SUPABASE_URL}/auth/v1/.well-known/jwks.json`. `SUPABASE_JWT_ISSUER` and `SUPABASE_JWKS_URL` can override those defaults. The verifier supports Supabase HS256, RS256, and ES256 access tokens. Set `SUPABASE_JWT_SECRET` only for projects using HS256. Keep all signing secrets server-side and never commit real secrets. Every data endpoint (`/api/analyse-csv`, `/api/bio/*`, `/api/cards`, `/api/cards/acknowledge`, and `/api/audit`) requires `Authorization: Bearer <Supabase access token>`; only `/api/health` is public. Invalid tokens return HTTP 401. Missing verifier configuration or verification-service failures return HTTP 503.

## Bioinformatics boundary

JLIGHT does not accept raw FASTA/FASTQ reads for in-product sequence analysis and does not implement TB resistance mutation calling. The Bioinformatics workspace reviews authorised outputs generated by validated external pipelines (for example, TBProfiler), preserving dataset identity, pipeline/database versions, QC, provenance and review history. Raw sequence processing and clinical interpretation remain outside JLIGHT.

## Deploy with Docker

```bash
# Build
docker build -t jlight-backend .

# Run (without DB — stateless mode)
docker run -p 5000:5000 jlight-backend

# Run (with PostgreSQL)
docker run -p 5000:5000 \
  -e DATABASE_URL=postgresql://user:password@host:5432/jlight \
  -e SECRET_KEY=your-secret-key \
  jlight-backend
```

## Connecting to the JLIGHT Frontend

The frontend (`index.html`) already calls these exact endpoints:
- `/api/analyse-csv` — when a CSV is uploaded
- `/api/bio/*` — when bioinformatics functions run
- `/api/health` — system monitor page

Change the base URL in the frontend from relative paths to your backend URL:

```javascript
const API_BASE = 'https://your-backend.render.com'
// Then: fetch(`${API_BASE}/api/analyse-csv`, ...)
```

## Standards Compliance

- ISO 15189 — QC CV% threshold (3.0%), Westgard implementation
- NICD NGS Guidelines 2024 — GC content thresholds for MTBC WGS
- Imported bioinformatics results must identify their source pipeline, software/database version, input dataset, QC and limitations
- POPIA — no patient-identifiable data stored; read-only integration model
